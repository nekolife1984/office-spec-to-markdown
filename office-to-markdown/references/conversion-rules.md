# 変換ルール（共通）― Word / Excel / PDF仕様書 → Markdown

office-to-markdown スキルの詳細ルール。
再構成の段階で、office-docs-readerスキルの抽出物（`extracted.md`、`inventory.json`、`media/`、`work/shapes.json`）を材料に適用する。
ルールによって判断が必要になった場合は、黙って決めずに納品報告に記載する。

## 共通ルール（Word & Excel）

1. **先に抽出、後で書き換え。** バイナリから直接再構成しない。
   office-docs-readerの抽出物（`extracted.md`、`shapes.json`、`inventory.json`）を材料にする。
2. **個数が契約である。** 出力の見出し・表・図形テキスト・コメント・メディアファイルは `inventory.json` と照合できなければならない。
3. **図は既定がdrawio.svg、難しいものはPNG。**
   - 箱・矢印・テキストでできた図（フロー図、画面遷移、状態遷移、構成図、組織図など）→ **`.drawio.svg`** に描き直す。
     Markdownで表示できるSVGにdiagrams.net（draw.io）のグラフが埋め込まれているため、変換後も図を編集できる。
     単純なノード／矢印の図には`scripts/make_drawio_svg.py`（JSON入力→.drawio.svg出力）を使う。
     リッチな図は.drawioソースを作成し、diagrams.netから図を埋め込んだSVGをエクスポートする。
   - 描き直した図は必ず検証する：埋め込みグラフがパースできること、ノード／矢印の個数とラベルが元の図と一致すること。
     検証が終わるまで元の描画（PNG）は作業フォルダに残す。
   - **難しい図はPNGのまま**：写真、スクリーンショット、高密度・精密な図、データのグラフ（チャート）、手書き・スキャンの図——描き直すと情報が落ちたり捏造になったりする恐れがあるものすべて。
     PNG参照＋短いテキスト説明（何を示すか、主要な値、結論）を付ける。
   - 一部だけ単純な図：構造はdrawio.svgに描き直し、何を簡略化したかを説明に書く。
4. **セル結合とGFMで表現できない表の扱い（優先順位つき）。**GFMのパイプ表にはセル結合（rowspan/colspan）の概念がないため、次の順で処理する：
   - **基本は「値の伝播」**：結合セルの値を、結合範囲の全セルに展開してパイプ表にする（グループ分けの結合は全行に値を繰り返す。
     列にまたがるタイトル結合は見出し化する）。
     「左上だけ値を残して他は空欄」は、空欄が「結合の続き」か「値なし」か区別できないため使わない。
   - **見た目が重要な表はHTML表**：結合した見た目そのものに意味がある、または伝播すると表が壊れる場合は、Markdown内にHTMLの`<table>` を埋め込み、`rowspan`/`colspan` で結合をそのまま保持する。
   - 複数段落のセル・入れ子の表は、上記で処理できない場合に限り、表の分割や定義リスト＋単純な表への分解で対応する。
   - いずれの方法でも、行や列を落とすことは決してしない。
5. **暗黙の意味は明示する。** 色、グレーアウト、ハイライト、取り消し線、セルの塗り——元で意味を持つものはテキストで表す（`<del>`、状態の列、注記）。
   装飾だけのものは落とし、報告で一度だけ触れる。
   なお太字・斜体・取り消し・下線は、Excel／PDFでは抽出の段階でMarkdown記法として保持されている（Wordはpandocが保持する）。
   保持された装飾は原則そのまま最終Markdownに引き継ぐ。
   文字色は抽出で個数だけが棚卸しに記録される（Excel: styled_cells、PDF: styled_spans）ので、色に意味がある場合はこの個数を手がかりに元資料を確認し、意味を言葉で明示する。
6. **相互参照。** 「図1／表2／項番」の番号を安定させる。
   再構成後に、すべての参照が実在する見出し・表・画像に解決することを確認する。
7. **罫線で描かれた図は「表」ではなく「図」として扱う。**セルの罫線で枠・矢印・レイアウトを描いて図を表現している箇所（Excel方眼紙の構成図・画面レイアウト図・枠組み図など）は、表への変換対象ではない。
   図のルール（ルール3）を適用し、再構成できるものは **drawio.svg** に描き直し、難しいものは **PNG** にする。
   罫線をパイプ表の区切りとして機械的に変換すると、図の構造が壊れて意味を失うため、絶対にしない。
   判定の目安：値のあるセルがまばらで罫線の密度が高い、罫線が不規則な矩形や接続を作っている、セル結合と罫線で「箱と線」を描いている。
   迷う場合はPDF描画を見て目視で判定する。

## 形式別のルール

形式ごとのルールはファイルが分かれている。
対象形式のものだけ読めばよい：

- Word（.docx）→ `conversion-docx.md`
- Excel（.xlsx）→ `conversion-xlsx.md`
- PDF → `conversion-pdf.md`

## 検証チェックリスト

- [ ] シート数／セクション数／ページ数が元と一致する（非表示シートの扱いの判断、PDFのヘッダー・フッター除去を含む）
- [ ] すべての表の行数・列数が照合済み
- [ ] 出力の図形テキスト数 ＝ `inventory.json` のテキスト付き図形数
- [ ] コメントは全て配置済み、または理由付きで明示的に除外
- [ ] `media/` のメディアファイルが全て参照されている。
  画像リンク切れなし（`verify.py`）
- [ ] 図：drawio.svgに描き直し済み（埋め込みグラフがパースでき、ノード／矢印の個数とラベルが元と一致）、または難しいものはPNG＋説明あり
- [ ] 相互参照（図・表・項番）がすべて解決する
- [ ] 納品報告に列挙する：落としたもの（レイアウト、色、ヘッダー）、画像/PDFのままにしたもの、判断した箇所すべて
