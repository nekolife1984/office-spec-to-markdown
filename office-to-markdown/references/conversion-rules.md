# 変換ルール ― Word / Excel仕様書 → Markdown

office-to-markdown スキルの詳細ルール。再構成の段階で、office-docs-reader
スキルの抽出物（`extracted.md`、`inventory.json`、`media/`、
`work/shapes.json`）を材料に適用する。ルールによって判断が必要になった
場合は、黙って決めずに納品報告に記載する。

## 共通ルール（Word & Excel）

1. **先に抽出、後で書き換え。** バイナリから直接再構成しない。
   office-docs-readerの抽出物（`extracted.md`、`shapes.json`、
   `inventory.json`）を材料にする。
2. **個数が契約である。** 出力の見出し・表・図形テキスト・コメント・
   メディアファイルは `inventory.json` と照合できなければならない。
3. **図は既定がdrawio.svg、難しいものはPNG。**
   - 箱・矢印・テキストでできた図（フロー図、画面遷移、状態遷移、
     構成図、組織図など）→ **`.drawio.svg`** に描き直す。Markdownで
     表示できるSVGにdiagrams.net（draw.io）のグラフが埋め込まれて
     いるため、変換後も図を編集できる。単純なノード／矢印の図には
     `scripts/make_drawio_svg.py`（JSON入力→.drawio.svg出力）を使う。
     リッチな図は.drawioソースを作成し、diagrams.netから図を埋め込んだ
     SVGをエクスポートする。
   - 描き直した図は必ず検証する：埋め込みグラフがパースできること、
     ノード／矢印の個数とラベルが元の図と一致すること。検証が終わる
     まで元の描画（PNG）は作業フォルダに残す。
   - **難しい図はPNGのまま**：写真、スクリーンショット、高密度・精密な
     図、データのグラフ（チャート）、手書き・スキャンの図——描き直すと
     情報が落ちたり捏造になったりする恐れがあるものすべて。PNG参照＋
     短いテキスト説明（何を示すか、主要な値、結論）を付ける。
   - 一部だけ単純な図：構造はdrawio.svgに描き直し、何を簡略化したかを
     説明に書く。
4. **セル結合とGFMで表現できない表の扱い（優先順位つき）。**
   GFMのパイプ表にはセル結合（rowspan/colspan）の概念がないため、
   次の順で処理する：
   - **基本は「値の伝播」**：結合セルの値を、結合範囲の全セルに展開して
     パイプ表にする（グループ分けの結合は全行に値を繰り返す。列に
     またがるタイトル結合は見出し化する）。「左上だけ値を残して他は
     空欄」は、空欄が「結合の続き」か「値なし」か区別できないため
     使わない。
   - **見た目が重要な表はHTML表**：結合した見た目そのものに意味が
     ある、または伝播すると表が壊れる場合は、Markdown内にHTMLの
     `<table>` を埋め込み、`rowspan`/`colspan` で結合をそのまま
     保持する。
   - 複数段落のセル・入れ子の表は、上記で処理できない場合に限り、
     表の分割や定義リスト＋単純な表への分解で対応する。
   - いずれの方法でも、行や列を落とすことは決してしない。
5. **暗黙の意味は明示する。** 色、グレーアウト、ハイライト、取り消し線、
   セルの塗り——元で意味を持つものはテキストで表す（`<del>`、状態の列、
   注記）。装飾だけのものは落とし、報告で一度だけ触れる。
6. **相互参照。** 「図1／表2／項番」の番号を安定させる。再構成後に、
   すべての参照が実在する見出し・表・画像に解決することを確認する。
7. **罫線で描かれた図は「表」ではなく「図」として扱う。**
   セルの罫線で枠・矢印・レイアウトを描いて図を表現している箇所
   （Excel方眼紙の構成図・画面レイアウト図・枠組み図など）は、表への
   変換対象ではない。図のルール（ルール3）を適用し、再構成できる
   ものは **drawio.svg** に描き直し、難しいものは **PNG** にする。
   罫線をパイプ表の区切りとして機械的に変換すると、図の構造が
   壊れて意味を失うため、絶対にしない。判定の目安：値のあるセルが
   まばらで罫線の密度が高い、罫線が不規則な矩形や接続を作っている、
   セル結合と罫線で「箱と線」を描いている。迷う場合はPDF描画を
   見て目視で判定する。

## Word（.docx）のルール

- 見出しレベルは段落スタイル（見出し1/Heading 1 …）から決める。
  フォントサイズや太字から決めない。
- 主ルートは pandoc の `-t gfm --wrap=none --extract-media=<dir>`。
  `--wrap=none` で1段落1行になり、差分が読みやすくなる。
- SmartArt、テキストボックス、浮動図形、Wordに埋め込まれたExcelグラフは
  pandocでは変換されない。検出し（画像として現れるか、全く現れない）、
  文書をPDFに書き出して該当領域をPNGに切り出し、drawio.svgに描き直す
  （箱・矢印・テキストの図）か、PNG＋テキスト説明のままにする
  （難しい図）。
- 変更履歴：既定は確定（承認済み）状態を変換する。ユーザーが変更履歴
  自体を明示的に求める場合だけ `--track-changes=all` を使う。
- ヘッダー、フッター、ページ番号、目次フィールド：落とす。目次が要る
  場合はMarkdownの見出しから再生成する。
- 脚注はpandocで `[^n]` として残る。本文に重複していないか確認する。

## Excel（.xlsx）のルール

Excel仕様書シートはセル格子上の自由形式レイアウトなので、変換前に
各シートを分類する：

| シート種別 | 変換方法 |
|---|---|
| データ表（項目定義・一覧） | 論理的な表ごとにMarkdown表を1つ。結合したヘッダーセルは下／右へ値を伝播させ、すべての行が自分のグループを分かるようにする |
| 画面仕様 | 見出し＋項目表に再構成する。画面キャプチャは画像のまま。画像内の項目番号と表の行が一致すること |
| 文章（概要・説明文） | 散らばったセルを読み順（上→下、左→右）に段落へ統合する。巨大でスカスカな表のまま出さない |
| 図主体（フロー図・構成図） | 図をdrawio.svgに描き直し、テキストでの解説を付けた短いMarkdownセクションから参照する。忠実な描き直しができないほど高密度・精密な場合は、PNG描画を参照し、その理由を書く |
| 表紙・改訂履歴 | 表紙→タイトル＋メタ情報リスト。履歴→単純な表 |

処理の細部：

- **結合セル**：共通ルール4の優先順位に従う。基本は値の伝播
  （グループ分けは全セルへ展開、列にまたがるタイトルは見出し化）。
  見た目が重要な表だけHTML表で `rowspan`/`colspan` を保持する。
- **図形・テキストボックス・吹き出しのテキスト** には本物の仕様文が
  入っていることが多い。すべて抽出し（office-docs-readerが
  `xl/drawings/*.xml` から行う）、アンカーセル順に並べ、それが注釈
  しているセクションへ吸収する。図形の自動名（「正方形/長方形 15」）を
  見出しとして残してはいけない。
- **セルコメント** は仕様の注記である。抽出し、該当項目の説明へ
  注記として統合する。
- **非表示のシート・行・列**：報告に列挙する。非表示シートは、
  ユーザーが作業用でないと確認した場合だけ変換する。
- **数式**：キャッシュ値を出力する。数式自体が仕様（計算ルール）の
  場合は、数式を別途抽出し（`openpyxl` の `data_only=False`）、
  値＋数式で提示する。
- **グラフ** はオブジェクトであり画像ではない。Excel/LibreOfficeで
  PNGに描画する。数値が重要な場合は、元データ範囲も表として抽出する。
- **セル内画像**（新しいExcel）は浮動画像のようにはアンカーしない。
  `media/` に抽出されるので、セルのリッチ値メタデータで照合するか、
  PDF描画と視覚的に照合して配置する。
- **罫線**：罫線は抽出（extract.py のセル値）には現れないため、
  「罫線で図を描いている箇所」はPDF描画か元ファイルの目視で検出
  する。検出した箇所は共通ルール7に従い、表ではなく図として
  drawio.svg／PNG に変換する。表の罫線（通常のデータ表の区切り）は
  変換対象ではなく、Markdown表では再現しない（構造で代替する）。
- **読み順** は自由形式シートでは曖昧である。迷ったらシートをPDFに
  書き出し、描画されたレイアウトを順序と「どの図形がどの表のものか」
  の正解として使う。

## PDFのルール

PDFはページレイアウトが固定された形式で、見出し・段落といった論理構造を
持たない。構造は「復元」するものであり、抽出にそのままは現れない。

- **見出し階層の復元**：フォントサイズ・太字・番号付けとしおり（目次）を
  手がかりに階層を決める。抽出のページ区切り（`## ページ N`）は作業用の
  区切りであり、最終Markdownには原則として残さない（ページ参照が必要な
  資料では注記として残す）。
- **ヘッダー・フッター・ページ番号の除去**：全ページの同じ位置に繰り返し
  現れるテキストは本文ではない。除去し、除去したことを報告に書く。
- **読み順**：複数段組（2カラム）や図の回り込みがある場合、抽出の並びが
  そのまま読み順とは限らない。ページ描画と照合して並べ替える。
- **表**：検出された表はそのまま使うが、ページをまたぐ表は1つに統合し、
  各ページで繰り返されるヘッダー行は先頭の1回だけにする。罫線のない表は
  検出漏れがあり得るため、ページ描画で目視確認する。結合セルの扱いは
  共通ルール4に従う。
- **図**：埋め込み画像とベクター描画が対象。共通ルール3（drawio.svg
  既定・難しいものはPNG）を適用する。ベクター描画の図はページを描画
  して該当領域を切り出してから判定する。グラフ（チャート）は原則PNG。
- **スキャンPDF**：readerの警告が出たページはOCRが前提。OCRなしに
  変換済みとして出してはいけない。OCR結果を使う場合はその旨を報告に
  書く。
- **リンク・しおり**：内部リンクやしおりは見出し構造の手がかりになる。
  外部リンクはMarkdownのリンクとして保持する。

## 検証チェックリスト

- [ ] シート数／セクション数／ページ数が元と一致する（非表示シートの扱いの判断、PDFのヘッダー・フッター除去を含む）
- [ ] すべての表の行数・列数が照合済み
- [ ] 出力の図形テキスト数 ＝ `inventory.json` のテキスト付き図形数
- [ ] コメントは全て配置済み、または理由付きで明示的に除外
- [ ] `media/` のメディアファイルが全て参照されている。画像リンク切れなし（`verify.py`）
- [ ] 図：drawio.svgに描き直し済み（埋め込みグラフがパースでき、ノード／矢印の個数とラベルが元と一致）、または難しいものはPNG＋説明あり
- [ ] 相互参照（図・表・項番）がすべて解決する
- [ ] 納品報告に列挙する：落としたもの（レイアウト、色、ヘッダー）、画像/PDFのままにしたもの、判断した箇所すべて
