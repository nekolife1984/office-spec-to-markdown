# 抽出ノート（共通）― 形式別の内部構造への案内

どちらの形式も、XMLパーツをまとめたZIPアーカイブである。
ライブラリが表に出してこない内容がある場合は、「その内容は存在しない」と結論づけず、パーツを直接読むこと。

形式ごとの内部構造（どこに何が入っているか）は、形式別のノートに分かれている。
対象形式のものだけ読めばよい：

- Word（.docx）→ `extraction-docx.md`
- Excel（.xlsx）→ `extraction-xlsx.md`
- PDF → `extraction-pdf.md`

## トラブルシューティング

- **画像が抽出できたがアンカーが分からない**：内容で照合する。
  浮動画像のアンカーはopenpyxlの `ws._images` で取れる。
  画像バイトのハッシュ（`img._data()`）を取り、`xl/media/*` のファイルと照合する。
  ファイル名だけでは位置は分からない。
- **シートが見当たらない**：棚卸しの `sheet_state` を確認する。
  非表示・完全非表示（veryHidden）のシートも、ユーザーが作業用だと言うまでは実在の内容として扱う。
- **数値がおかしい**：日付・時刻セルはXML内ではシリアル値であり、openpyxlなどのライブラリがセルスタイルから変換している。
  数式セルは最後にExcelで保存したときのキャッシュ値を示すため、別ツールが作ったファイルでは古いことがある。
- **日本語が文字化けする**：XMLはUTF-8。
  文字化けはたいてい自作パーサが共有文字列を誤ったエンコーディングで読んだ場合に起きる。
  即席の文字列処理よりopenpyxl/pandocを優先する。
- **巨大なシート**：自由形式の仕様書シートは、使用範囲が大きく、書式だけの空セルで埋まっていることがある。
  末尾の全空行・全空列を切り落として（extract.pyは実施済み）からLLMに渡す。
